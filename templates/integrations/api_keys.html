How to call it

Every call sends Authorization: Bearer <key> and JSON. The key decides the workspace. People are named the respond.io way: phone:+27821234567, id:123 or email:name@example.com.

Create or update a contact

curl -X POST '{{ base_url }}contact/create_or_update/phone:+27821234567' \
  -H 'Authorization: Bearer <key>' -H 'Content-Type: application/json' \
  -d '{"firstName": "Thabo", "lastName": "Mokoena", "email": "thabo@example.com",
       "custom_fields": [{"name": "policy_number", "value": "GAP12345"}]}'
→ {"contactId": 42}

Send an approved template (works any time)

curl -X POST '{{ base_url }}contact/phone:+27821234567/message' \
  -H 'Authorization: Bearer <key>' -H 'Content-Type: application/json' \
  -d '{"channelId": {{ channels.0.pk|default:1 }},
       "message": {"type": "whatsapp_template",
                   "template": {"name": "policy_reminder", "languageCode": "en",
                                "components": [{"type": "body", "parameters": [
                                    {"type": "text", "text": "Thabo"}, {"type": "text", "text": "GAP12345"}]}]}}}'
→ {"contactId": 42, "messageId": "…", "status": "sent"}

Send text or a file (only within 24 hours of the person's last message)

-d '{"message": {"type": "text", "text": "Your claim has been paid."}}'
-d '{"message": {"type": "attachment", "attachment": {"type": "file", "url": "https://…/statement.pdf", "fileName": "statement.pdf"}}}'
  • GET {{ base_url }}contact/phone:+27821234567 returns the contact.
  • Leaving out channelId uses this workspace's main number. The template language must match WhatsApp exactly: en_US is not en.
  • Answers: 200 sent · 400 something in the request is wrong (the message says what) · 401 bad key · 422 not sent because the person replied STOP or this server is in test mode · 502 WhatsApp refused it.
  • A message sent here stops any workflow menu running in that chat, and when the person replies they go to the team, not the greeting menu.
